# 桌面图标开关（DesktopIconToggle）

双击桌面空白处，隐藏 / 显示桌面图标。纯 Win32 单文件小程序（约 210 KB），常驻托盘，
免安装、无运行时依赖，空闲时几乎不占资源。

> **下载**：到 [Releases](../../releases/latest) 取编译好的 `DesktopIconToggle.exe`，下载即用。
> 想自己编译请见 [从源码构建](#从源码构建)。

## 快速开始

1. 双击 `dist\DesktopIconToggle.exe`。程序没有主窗口，**直接进托盘**（一只眼睛的图标），
   并在同目录生成 `config.ini`。首次运行会弹一次提示气泡，说明怎么用。
2. **双击桌面空白处**即可在"显示图标 / 隐藏图标"之间切换。
   双击桌面上的图标不受影响，双击任务栏、其他程序窗口也不会误触发。
3. 右键托盘图标：切换图标显示、**开机自动启动**（可勾选）、**退出**。
   双击托盘图标也能直接切换。
4. 不想要托盘图标？见 [配置文件](#配置文件-configini)，改一行，再双击一次 exe 即可。

程序同一时刻只跑一个实例。**重复双击 exe 不是"提示已在运行"，而是让新实例接管旧实例**——
这既是"改完配置让它生效"的操作方式，也顺带避免了托盘图标被隐藏后没法退出的死结。

## 实测资源占用

Windows 10 22H2 / 1920×1080 / 125% 缩放，稳定运行后连续 20 秒采样：

| 指标 | 实测值 |
| --- | --- |
| 空闲 CPU | 20 秒累计 47 ms ≈ **单核 0.23%** |
| 私有内存 | **1.63 MB** |
| 工作集 | 8.2 MB（含共享的系统 DLL 页） |
| 线程 / 句柄 | 4 / 131 |

运行期间**不碰配置文件、不轮询任何东西**：整个程序只由鼠标事件驱动，钩子每收到一个事件
只做一次整数比较就返回。上面那点 CPU 全部来自采样期间经过本进程的鼠标事件，鼠标不动就是 0。

## 配置文件 config.ini

程序**第一次运行会在 exe 同目录自动生成 `config.ini`**（UTF-8、带中文注释）。删掉它，
下次启动会自动重新生成。

```ini
[General]
; 1 = 显示（默认）   0 = 隐藏
ShowTrayIcon=1
```

设成 `ShowTrayIcon=0` 即隐藏托盘图标。双击桌面空白处的功能**完全不受影响**，只是没有托盘菜单了。

这个文件**只在程序启动时读一次**，运行期间不再访问（不为一个几乎不变的设置去反复碰磁盘）。
所以要让它生效就得重启：**改完保存后，重新双击一次 exe 即可**。

> **隐藏之后怎么退出、怎么恢复？**
> 把 `ShowTrayIcon` 改回 `1` 并保存，再双击一次 exe。正在运行的实例会自动退出、由新实例接管，
> 不需要去任务管理器，托盘图标就回来了，然后右键 → 退出。
> 万一遇到异常情况（旧实例卡住），用任务管理器结束 `DesktopIconToggle.exe` 再启动即可。

读取配置很宽容，下面这些写法都能正确识别：

* 文件带不带 UTF-8 BOM、用 UTF-16 还是 ANSI 保存；
* `ShowTrayIcon = 0`（等号两边有空格）、键名大小写不同；
* `#` 或 `;` 当注释符、值后面跟别的内容。

配置读不出来或文件被改坏时，一律回退到默认值（**显示**托盘图标）——保证不会因为改错配置就找不回来。

## 命令行参数

日常用不到，保留作脚本调用和故障排查：

| 参数 | 作用 |
| --- | --- |
| 无参数 | 常驻托盘（正常使用方式） |
| `--toggle` | 切换一次图标显示状态后退出 |
| `--diag` | 把当前状态 + 全屏栅格命中测试结果写入 exe 同目录 `diag.txt` |
| `--click x y` | 对屏幕坐标 (x, y) 走一遍完整判定逻辑（判定为空白则真的切换），结果写 `diag.txt` |
| `--dblclick x y` | 合成一次真实双击，用于端到端自检 |
| `--trace` | 常驻，并把**每一次双击的判定过程**追加写入 `trace.log` |

排查"双击没反应"时，用 `--trace` 启动，复现一次，然后看 `trace.log` —— 里面会写清是
命中了图标、还是被别的窗口挡住、还是真的执行了切换。

## 从源码构建

需要 **Visual Studio 生成工具（含"使用 C++ 的桌面开发"工作负载）** + **Windows 10/11 SDK**。
生成图标还需要 Python + Pillow（仅当 `src/app.ico` 不存在时调用）。

```powershell
pwsh -ExecutionPolicy Bypass -File build.ps1
```

构建脚本**不依赖 vcvars，也不经过 cmd.exe**：它自己定位 MSVC 与 SDK、设置 `INCLUDE`/`LIB`
后直接调用 `cl.exe`。少一层命令行解释器，也就少一类"路径含非 ASCII 字符被码页破坏"的坑。
产物为 `dist\DesktopIconToggle.exe`（静态链接 CRT，无 VC++ 运行库依赖）。

`.github/workflows/build.yml` 会在 windows-latest 上自动编译验证；推 `v*` 标签
（`git tag v1.0.0 && git push --tags`）会自动创建 Release 并把 exe 附上去。

目录结构：

```
src\main.cpp                     全部源码（单文件）
src\app.rc                       图标资源
src\app.ico                      程序/托盘图标（由 tools\make_icon.py 生成，已纳入版本管理）
tools\make_icon.py               图标生成脚本
build.ps1                        构建脚本
.github\workflows\build.yml      CI：自动编译 + 打标签时自动发 Release
dist\                            构建产物（不进仓库）
dist\config.ini                  配置文件（程序第一次运行时自动生成）
```

## 卸载

1. 右键托盘图标 → 退出。（托盘图标若被配置隐藏，先把 `ShowTrayIcon` 改回 `1`）
2. 删除整个文件夹（含 `config.ini`）。
3. 如果开过开机自启：先在托盘菜单里取消勾选，它会删掉注册表
   `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 下的 `DesktopIconToggle` 值。
   忘记取消也不要紧——删掉 exe 后那条自启会指向不存在的文件，手动删掉即可。
   程序还会在 `HKCU\Software\DesktopIconToggle` 留一个"已提示过"的标记，可一并删除。

## 实现要点

这几条都是实测踩出来的，记录一下，改动代码时别踩回去。

**1. 切换图标用的是 Explorer 自己的命令，不是障眼法**

向桌面容器窗口 `SHELLDLL_DefView` 发 `WM_COMMAND`，命令 ID `0x7402`。这正是桌面右键菜单
「查看 → 显示桌面图标」的同一个命令，所以：

* 状态是 Explorer 的真实状态，重启资源管理器后依然保持；
* 桌面右键菜单里的勾选状态正确，不会和程序"打架"。

实测 `IsWindowVisible(SysListView32)` 与注册表 `HKCU\...\Explorer\Advanced\HideIcons`
完全同步（`0→1→0` 来回切换一致）。万一某个系统版本不响应这条命令，程序会自动回退到
直接 `ShowWindow` 列表视图。

**2. 双击是自己判定的，不能依赖 `WM_LBUTTONDBLCLK`** ← 关键

系统只在"鼠标下的窗口带 `CS_DBLCLKS` 类风格"时才生成 `WM_LBUTTONDBLCLK`。
桌面图标**隐藏之后**，鼠标底下变成 `SHELLDLL_DefView` / `WorkerW`，无法保证它们带这个风格——
一旦不带，图标隐藏后就**再也无法用双击显示回来**。实测确实如此：钩子只收到
down/up/down/up，那条消息根本没出现过。

现在改成按系统同样的参数自行配对（`GetDoubleClickTime()` + `SM_CXDOUBLECLK`/`SM_CYDOUBLECLK`），
行为与系统一致，但不依赖目标窗口的类风格。

**3. 进程必须 DPI 感知**

低级鼠标钩子回传的是**物理像素**坐标，而 DPI 不感知的进程里 `WindowFromPoint` / `GetCursorPos`
用的是被虚拟化的坐标。在 125% 缩放下两者相差 1.25 倍——实测请求 (1062,718) 时钩子收到
(1328,898)，命中判断会落在完全错误的位置。程序启动时动态调用 `SetProcessDpiAwarenessContext`
（逐级降级到 `SetProcessDpiAwareness` / `SetProcessDPIAware`），保证坐标空间一致。

**4. 区分"空白"和"图标"：跨进程命中测试**

桌面图标是 `SysListView32` 画的，图标不是独立窗口，所以 `WindowFromPoint` 区分不出来。
做法是在 explorer 进程里分配一块 `LVHITTESTINFO`（`VirtualAllocEx` + `WriteProcessMemory`），
发 `LVM_HITTEST` 后读回 `iItem`：`iItem < 0` 就是空白。

两个易错点：坐标要经 `MapWindowPoints` 换算成列表视图的**客户区**坐标（多显示器必须）；
命中测试失败时回退到"热项 / 选中项"启发式判断。

实测 880 个采样点：空白 569 / 图标 311 / **无法判定 0**，识别出的图标点精确落在
(24,24)、(72,24)、(120,24)，正是桌面图标的位置。

**5. 钩子回调里绝不做重活**

回调只做双击配对，然后 `PostMessage` 把坐标丢给自己的窗口过程，判定与跨进程调用全部在
窗口过程里执行。这样回调永远立即返回，不会因为超时触发系统的 `LowLevelHooksTimeout`
而被**静默摘除钩子**（那样程序会突然失效且毫无提示）。

另外窗口用 `WS_EX_TOOLWINDOW` 且从不 `ShowWindow`，所以不会出现在 Alt+Tab 和任务栏里。

## 已知限制

* **只在桌面处于最上层时生效。** 桌面被其他窗口挡住时双击不会切换——这是有意的，
  否则双击别的程序会意外隐藏你的桌面图标。
* 桌面图标只能显示在主显示器上，这是 Windows 的行为，非本程序限制。
* 钩子是全局低级鼠标钩子。所有鼠标事件都会经过本进程一次（仅一次整数比较），
  这是该功能无法避免的最小代价。

## 实现要点（配置部分）

配置文件**没有**用 `GetPrivateProfileIntW` 这套 API 来读，原因是它有进程级缓存：
外部改完文件再读，很可能拿到的还是旧值；而按文档用
`WritePrivateProfileString(NULL, NULL, NULL, path)` 去"清缓存"，它会先把缓存内容**写回磁盘**，
正好会覆盖掉用户刚做的修改。

所以这里自己读文件、自己解析：兼容 UTF-8（带不带 BOM）/ UTF-16LE / ANSI，键名大小写不敏感，
支持 `;` 和 `#` 注释和等号两边空格，读不出就用默认值。只认 `[General]` 节，
代码见 `LoadConfig` / `ParseIniInt`。

**只在启动时读一次**，运行期间不监听文件变化。这是有意的：为一个几乎不变的设置去常驻一个
`WM_TIMER` 轮询或者 `ReadDirectoryChangesW` 监听线程，都属于白付代价。

代价是"改了配置要重启才生效"，而托盘图标一旦被隐藏就没有菜单可点、退不掉，容易变成死结。
所以补了一条**新实例接管**：启动时如果发现已有实例，就给它发一条消息请它退出，然后由新的实例接管。
于是"改完配置重新双击一次 exe"就是完整的生效流程，不需要动用任务管理器。

配套的一个坑：程序自己读写 `trace.log` / `config.ini` 时**必须拼 exe 目录的绝对路径**，
用相对路径会按"当前工作目录"解析，从别处启动就会写到别的地方去（`PathBesideExe` 就是干这个的）。

## 兼容性

在 Windows 10 22H2（19045）+ 125% DPI 缩放的 x64 机器上实测通过。
代码按 Windows 7 及以上编写（DPI 相关 API 都是动态获取、逐级降级），
但只在 Windows 10 上验证过，Windows 11 未实测。
